# Stefan Mandovski — Portfolio

Personal portfolio and CV for Stefan Mandovski, Senior QA Automation Engineer.
Static HTML, CSS and vanilla JavaScript — no framework, no build step, no
runtime dependencies beyond Google Fonts.

The site is also a working QA project: it ships its own Playwright suite, and
`qa-suite.html` is the dashboard for that suite, published by CI.

## Structure

```
index.html                 landing page
cv.html                    résumé (screen + print), source of the PDF
qa-suite.html              dashboard for this repo's own Playwright runs
404.html                   not-found page (works at any path depth)
assets/css/                styles.css (site) + print.css (CV on paper)
assets/js/main.js          nav, timeline label, floating CTA, hash routing
assets/js/qa-suite.js      renders assets/qa/*.json
assets/qa/                 report.json, history.json, test-history.json — generated
assets/cv/                 CV PDF — generated by `npm run cv:pdf`
reporters/                 custom Playwright reporter + the report's types
scripts/serve.mjs          static server for tests and previews (404s like GitHub Pages)
scripts/build-cv-pdf.mjs   renders cv.html to the PDF with Playwright
tests/                     Playwright suites, fixtures and dashboard test helpers
docs/decisions/            why things are built the way they are
```

## Run locally

Requires Node.js 20+.

```bash
npm install
npm run playwright:install   # Chromium, Firefox, WebKit — first time only
npm run serve                # http://127.0.0.1:8000
npm test                     # every suite on every browser
```

Serve over HTTP rather than opening files directly: `fetch()`, relative paths
and the download attribute all behave differently over `file://`.

## Test suites

Every test runs on four projects — `desktop-chromium`, `desktop-firefox`,
`desktop-webkit` and `mobile-chromium` — except where a capability only exists
in one engine (noted below). Suites are tagged, so any one can run on its own:

| Tag | File | What it proves | Techniques |
| --- | --- | --- | --- |
| `@smoke` | `smoke.spec.ts` | Navigation, timeline, skill bars, floating CTA, scroll on reload, skip link, retired/unknown anchors, real 404 status and a styled 404 at any depth, CV page, asset versions, mobile nav | `page.clock`, `emulateMedia({ reducedMotion })`, `expect.poll`, `request` fixture |
| `@a11y` | `a11y.spec.ts` | Zero WCAG 2.2 A/AA violations on every page and browser; the page outline and nav as a screen reader receives them; visible focus on every control | `@axe-core/playwright`, `toMatchAriaSnapshot` |
| `@print` | `cv-print.spec.ts` | Print CSS hides screen chrome and never splits a role across pages; the CV fits 4 A4 pages; the committed PDF isn't stale | `emulateMedia({ media: 'print' })`, `page.pdf()` (Chromium) |
| `@perf` | `performance.spec.ts` | LCP, CLS and bytes-over-the-wire stay inside a budget on a throttled profile | CDP network + CPU throttling, `PerformanceObserver`, `expect.soft` (Chromium) |
| `@dashboard` | `qa-dashboard.spec.ts` | The dashboard renders any run correctly — failures, flaky tests, a11y violations, blown budgets, stability history, tag filtering — and degrades gracefully when files are missing or unreachable | `page.route` (fulfill / abort), fixture-provided page object, typed report builders |
| `@showcase` | `showcase.spec.ts` | A recruiter's journey, recorded with trace and video on every run | `test.step`, per-file `trace`/`video`/`slowMo` |

Cross-cutting, via `tests/fixtures.ts`:

- an **auto fixture** fails any test whose page throws an uncaught exception —
  "no JS errors" is enforced on every journey, not asserted once;
- `makeAxeBuilder` and `dashboard` fixtures keep setup out of the tests.

```bash
npm run test:a11y            # or test:smoke, test:print, test:perf, test:dashboard
npx playwright test --project=desktop-webkit
npm run qa:report            # run everything and regenerate assets/qa/* locally
```

## The dashboard pipeline

`reporters/qa-dashboard-reporter.ts` is a Playwright `Reporter`. Given a run,
it writes:

- `assets/qa/report.json` — totals, per-browser and per-tag counts, every test,
  accessibility results, performance results and the showcase recording;
- `assets/qa/history.json` — one summary per run (last 30), for the trend;
- `assets/qa/test-history.json` — per-test outcomes and durations across runs
  (last 20), for the Stability panel: tests that failed or needed a retry, and
  tests running much slower than their usual pace;
- `assets/qa/artifacts/<id>/` — `trace.zip` and video for failed or flaky tests
  and for the showcase journey. The dashboard links traces straight into
  [Playwright's Trace Viewer](https://trace.playwright.dev).

Tests feed it through annotations (`qa:a11y`, `qa:perf`, `qa:showcase`) rather
than side files, so the data travels inside Playwright's own results — which is
what lets it survive the blob merge in CI.

When `GITHUB_STEP_SUMMARY` is set, the reporter also writes a run summary onto
the GitHub Actions run page.

## CI and deployment

`.github/workflows/ci.yml`, on every push and pull request:

```
desktop-chromium ─┐
desktop-firefox  ─┤
desktop-webkit   ─┼─→ report ─→ deploy (main only)
mobile-chromium  ─┘
```

1. **test** — one job per browser, in parallel, each writing a blob report.
   Browsers are cached per Playwright version.
2. **report** — runs even when tests fail. `merge-reports` feeds all four blobs
   to the HTML reporter and the dashboard reporter in one pass. On `main`, the
   JSON files are committed back (`[skip ci]`); traces and videos are uploaded
   as a workflow artifact instead of being committed.
3. **deploy** — only when every browser passed. Publishes the site plus the
   trace/video artifact to GitHub Pages.

To enable Pages: **Settings → Pages → Source: GitHub Actions**.

**Manual runs:** Actions → CI → **Run workflow**. Choose all browsers or one,
optionally narrow to a tag or regex (`@a11y`, `@smoke`, `skill bars`), and decide
whether a run on `main` publishes. Only a full run — every browser, no filter —
can commit dashboard data and deploy, so the dashboard never presents a partial
suite as the whole thing.

Because the report job commits to `main`, run `git pull` before pushing again.

## Editing notes

- Bump the `?v=` query on `styles.css` / `main.js` / `qa-suite.js` when you
  change them. `@smoke` fails if the four pages disagree on the stylesheet.
- After editing `cv.html` or `print.css`, run `npm run cv:pdf`. `@print` fails
  if the committed PDF has fallen behind the page.
- `index.html`'s Experience section and `cv.html`'s are intentionally
  duplicated (browse vs print) to keep the site dependency-free.
- Don't hand-edit `assets/qa/*` — every run regenerates them.
- Running every browser locally is heavy; if Firefox times out under load, use
  `--workers=2` or run one project at a time. CI gives each browser its own
  machine.

## What broke along the way

Real defects this setup caught before they shipped:

- The "mobile" project used the iPhone 13 descriptor, which defaults to
  **WebKit** — while CI only installed Chromium. Every mobile test would have
  failed on the first push. Fixed by pinning `browserName: "chromium"`.
- Selectors written for one project card broke silently when a second card
  arrived (**strict mode violation**). Scoped by content instead.
- `python3` on Windows is a Microsoft Store stub, so the test server never
  started locally. Replaced with `scripts/serve.mjs`.
- axe flagged `--ink-faint` text at roughly **3:1 contrast**; the token was
  darkened to pass 4.5:1 in both themes.
- The CV printed to **7 A4 pages** because screen section padding leaked into
  print. Print styles now hold it to 3, and `@print` keeps it there.
- The skip link's `#main` target would have been routed to the 404 page by the
  unknown-hash handler. Caught by the keyboard test.

See [docs/decisions](docs/decisions) for the reasoning behind the larger choices.
